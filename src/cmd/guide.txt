apm: a small project tracker for agents and humans (projects, milestones, tasks, subtasks,
assignees, a task log, pages, tags, links, history, custom statuses and attributes) and
the shared memory of the agents that use it. One SQLite file.

SETUP
  Database: --db PATH > $APM_DB > ~/.agent-pm/apm.db (created on first use).
  Actor:    --as NAME > $APM_AGENT > OS user. Recorded as created_by and comment author.
  Agents: set APM_AGENT once per session and always pass --json.

JSON CONTRACT (--json, works on every command)
  Success: one JSON object or array on stdout. Writes return the written object.
  Errors:  {"error": "<msg>"} on stderr. Exit 1 = command failed, 2 = invalid arguments.
  `next` prints {"task": <task>|null, "renewed": bool} (+ "context" with --context);
  no task ready = exit 3.
  Without --json: short text lines, errors as `error: <msg>`. apm never prompts.

IDS
  Project KEY: 1-10 letters/digits, starting with a letter (APM). Case-insensitive.
  Task KEY-N: APM-12, numbered per project, never reused.
  Old ids keep resolving after `move` or `project edit --key`; output shows current ids.
  Milestones, statuses and custom attributes are named within a project (-p KEY).

WORKFLOW
  apm project add APM "agent-pm" -d "the tracker"
  apm milestone add v1 -p APM --due 2026-12-01
  apm add "parse args" -p APM -m v1 -a alice --priority high
  apm add "flag tests" --parent APM-1                # subtask, same project
  apm start APM-1                                    # first active status: doing
  apm comment APM-1 "clap derive works; tests next"
  apm done APM-2
  apm list -p APM -a alice                           # open tasks only
  apm list -p APM --status done,cancelled            # explicit statuses
  apm list -m v1 --all                               # include done/cancelled
  apm show APM-1                                     # fields, subtasks, attrs, comments
  apm show APM-1 --tree                              # the task and all its subtasks
  apm edit APM-1 --priority urgent --unset due
  apm milestone list -p APM                          # progress done/total
  apm milestone close v1 -p APM

CUSTOM ATTRIBUTES
  apm attr add size -p APM --type select --options s,m,l
  apm attr add points -p APM --type number    # types: text number select date datetime checkbox
  apm add "cache layer" -p APM --set size=m --set points=3
  apm list -p APM --where size=m
  apm edit APM-3 --unset points
  apm attr list -p APM

STATUSES
  apm status list -p APM                             # todo doing blocked done cancelled
  apm status add review -p APM --category active --position 3
  apm status edit doing -p APM --rename "in progress"
  apm edit APM-3 --status Review                     # names are case-insensitive
  apm status rm blocked -p APM --to review           # --to moves its tasks first

LINKS, TAGS, HISTORY
  apm link APM-1 blocks APM-3                        # kinds: blocks relates duplicates
  apm list -p APM --ready                            # open, no open blocker (or --blocked)
  apm edit APM-3 --tag perf --untag wip              # tags: lowercase a-z 0-9 _ : . -
  apm list --tag perf                                # repeatable: all must match
  apm tags -p APM                                    # tags by count
  apm history APM-3 --limit 5                        # latest 5 events, oldest first
  apm unlink APM-1 blocks APM-3

MOVE AND RENAME (old task ids and project keys keep resolving)
  apm project add OPS "operations"
  apm move APM-3 OPS                                 # now OPS-1; subtasks move too
  apm show APM-3                                     # finds OPS-1
  apm project edit OPS --key INFRA                   # OPS-1 is now INFRA-1
  apm attr edit points -p APM --rename estimate

EXPORT, IMPORT, BACKUP
  apm export -p APM -o apm.json                      # JSON, pages too; no -p = all projects
  apm import apm.json --key NEW --dry-run            # same KEY-N and history; all or nothing
  apm backup --keep 7                                # copy to backups/ next to the db

SEARCH, SORT, DUE
  apm edit APM-1 --due 2026-11-20T17:00+01:00        # date or date-time; stored in UTC
  apm list --search "clap" --sort -priority,due --limit 5   # title, body, comments
  apm list --due-after 2026-11-01 --due-before 2026-12-01   # strict bounds
  apm list --overdue                                 # open tasks due before now

AGENT LOOP (agents sharing a project each get their own task)
  apm add "release notes" -p APM --priority urgent
  apm next -p APM --context --as bot       # claim + assign + start the best task; its context
  apm comment APM-4 "draft in docs/notes.md" --as bot
  apm claim APM-4 --ttl 4h --as bot                  # renew (default 2h, max 7d)
  apm claims -p APM --mine --as bot                  # live claims, soonest expiry first
  apm done APM-4 --as bot                            # closing a task releases its claim

KNOWLEDGE (what you learn, kept for the next agent and for you after compaction)
  apm context APM-3                      # START HERE: task, handoff, log, questions, pages
  apm context                            # the task you hold a claim on; next --context too
  apm context -p APM                     # fresh session: pinned pages, questions, handoffs
  apm comment APM-3 "lock is per file"   # log: a finding on this task (add-only)
  apm comment APM-3 --kind question "WAL on NFS?"   # open until answered:
  apm comment APM-3 --answer 41 "no, rollback journal"
  apm comment APM-3 --kind handoff -     # before you stop: state, next, decisions + why, where
  apm page add APM:storage "Storage" -s "gist in one line" -b - --link APM-3 [--pin]
  apm page show APM:storage              # full text; --version N; page history APM:storage
  apm page edit APM:storage --append -   # add a section; --expect-version N guards rewrites
  apm page verify APM:storage            # re-read, still true (pages unchecked 30d are stale)
  apm search "busy timeout" -p APM       # pages, then log entries, best match first
  Log or page? Log = about this task, now. Page = stays true after the task closes
  (decision + why, architecture, convention, gotcha). --pin: shown with every task of KEY.
  apm guide --agents                     # lines to paste into AGENTS.md / CLAUDE.md

VALUES
  Status:   a status of the task's project; JSON has `status` and `status_category`.
  Category: todo | active | done | cancelled. New tasks get the first todo status;
            start = first active, done = first done, block = the status named blocked.
  Priority: none (default) | low | medium | high | urgent
  Text:     bodies and comments are Markdown by convention, stored verbatim. Long text:
            -b - (stdin) or --body-file PATH on add/edit; comment KEY-N - or --file PATH.
  Due:      YYYY-MM-DD, or YYYY-MM-DDTHH:MM[:SS] with Z or +HH:MM/-HH:MM (stored as UTC ...Z).
            A date bound (--due-before/--due-after) compares the UTC date part of a due.
  Sort:     id created updated due priority status title; -key = descending; no due last.
  Checkbox: true/false/yes/no/1/0. Date attributes: YYYY-MM-DD; datetime: like due.
  `list` hides done/cancelled-category tasks unless --all or --status.
  Blocked: open, with an open blocker or in a status named blocked; else --ready.
  Next:     your claimed task first; else ready, unclaimed, unassigned/yours/lapsed claimant's,
            by priority, due, id. Claims expire on their own; closing a task drops its claim.

COMMANDS
  project add|list|show|edit|rm   manage projects (edit --key re-keys; rm deletes all in it)
  add | list | show | edit | rm   tasks; filters: -p --status -a -m --parent --where --tag
                                  --ready --blocked --search --due-before --due-after
                                  --overdue; --sort --limit
  link | unlink A KIND B          blocks (no cycles), relates, duplicates; show lists both ends
  tags | history KEY-N            tag counts (-p KEY); a task's events (--limit N)
  start | done | block            status shortcuts
  move KEY-N PROJECT              move a task and its subtasks, renumbered in PROJECT
  next | claim | release | claims  claim work: --ttl, --steal, --force; claims -p --mine
  status list|add|edit|rm         custom statuses, -p KEY; a project keeps at least one
  milestone add|list|show|edit|close|reopen|rm   -p KEY; rm keeps its tasks
  attr add|edit|list|rm           custom attributes, -p KEY; edit --rename
  comment KEY-N TEXT|-            log entry (- reads stdin; --file); --kind --answer ID
  context [KEY-N] | context -p KEY  what earlier agents learned, one call (--log N)
  page add|show|edit|verify|list|history|rm   pages KEY:slug; --link --pin --append
  search TEXT                     pages and log entries, best first (-p KEY, --limit N)
  export | import FILE|- | backup  move projects between databases; copy the database
  guide | db                      this text (--agents: snippet); db path and schema version
  Every command has --help.
